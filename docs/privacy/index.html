Privacy

This page describes the hosted jevmod bot for Discord, effective 2026-09-18. Each statement points to the line of the source code it comes from; the list is in CLAIMS.md.

What the hosted bot sends to the model

For each message it judges, the bot sends the message text and the topic of the channel to Jev, the model run by TypeSafe.

It does not send the author's name, the author's id or the server's name. Messages are numbered by position inside the request and nothing else identifies them.

The author's id is kept only in the bot's own log so that erasure requests can be honoured.

Messages from members who can manage messages, and from roles you mark as trusted with /mod trust, are never sent to the model.

TypeSafe processes what it receives under its own terms: typesafe.ai.

What the hosted bot stores

The bot writes a record only when a message crosses one of your thresholds and gets an action (flag, delete or time out).

A message that passes is not written anywhere.

Each stored record holds: the message id, the author id, the first 80 characters of the channel topic, the category, its probability, the action taken, the probability of every category asked, a request id and a timestamp.

The record has a text column, but the hosted bot runs with JEVMOD_KEEP_TEXT_CHARS set to 0, so that column is always empty.

The store cuts the text to that many characters before writing it, and with 0 nothing of the text is written.

A test in the repository checks that setting.

Per server and per calendar month the bot also counts judged messages, model requests and tokens, for the quota.

Decision records are kept for 30 days.

Older records are deleted before every batch is judged.

Your settings (thresholds, actions, rules, trusted roles, channel topics, the id of the log channel) are stored for as long as the bot is in your server.

What stays in your Discord

Every flagged message is posted to a log channel as an embed that contains the first 500 characters of the message text.

That embed also mentions the author and the channel.

The log channel is created with the everyone role unable to read it.

That embed is a message in your server: Discord holds it, not jevmod. To remove it, delete the message or the log channel like any other content in your server.

When a message is deleted or a member is timed out, the member receives a direct message from the bot with the server name, the channel, the category and the confidence, and a note to contact the server's moderators.

Deleting data

/mod forget deletes the server's settings, usage counters, decision records, API keys and subscription row.

/mod forget_user @member deletes that member's decision records and replies with how many were removed.

Kicking the bot, or the bot leaving the server, deletes everything stored about that server.

All /mod commands require the Manage Server permission.

Payments

Payment for the Pro plan happens on a Stripe Checkout page opened from /mod upgrade.

jevmod stores, per server: the Stripe customer id, the subscription id, the price id, the subscription status and the end of the current period.

Stripe notifies jevmod of changes through a webhook; when a subscription is cancelled or stops being active the server goes back to the Free plan.

Managing or cancelling the subscription happens in Stripe's billing portal, reached through the same /mod upgrade command.

Card numbers are entered on Stripe's pages. See Stripe's privacy policy.

The demo on this site

The demo on the front page accepts up to 300 characters of text.

Each check is logged by the operator with the text, the category, the probabilities, a hash of your IP address, the country header set by the proxy, and the number of tokens it cost.

The IP address is hashed with SHA-256 and a salt before it is stored; the address itself is not kept.

Each address may run 6 checks per minute and 40 per day.

The demo has a monthly spend cap, $0.50 by default, and answers with an error once it is reached.

Demo records are deleted 90 days after they are written; the check that does it runs on every request.

The demo does not use the bot's database.

Analytics

A self-hosted Umami instance at analytics.hernandezbastos.es counts page views; it does not use cookies.

Self-hosted installs

If you run jevmod yourself, none of the above applies: the database is on your machine and the operator of this site never sees it.

A self-hosted copy keeps up to 300 characters of each flagged message by default; set JEVMOD_KEEP_TEXT_CHARS=0 to keep none.

Discord permissions the bot asks for and why

  • View Channels: to receive the messages it judges.
  • Send Messages: to post decisions in the log channel.
  • Manage Channels: to create the private #jevmod-log channel the first time it needs it.
  • Manage Messages: to delete a message, only when you set a category or rule to delete or timeout.
  • Moderate Members: to time a member out, only when you set a category or rule to timeout.
  • Add Reactions: to add the ❌ and ✅ reactions under each log entry.
  • Embed Links: the log entry is an embed.
  • Read Message History: to fetch the log entry you reacted to, so it can adjust the threshold.

Separately from the permissions above, the bot has Discord's Message Content intent enabled; without it Discord does not deliver message text to bots.

The invite link asks for those eight permissions and no others.

If a permission is missing, the bot records "missing permissions to act" in the log entry and does nothing else.

The bot has no code path that bans anyone; the only actions it knows are off, flag, delete and timeout.
